You are the panel. Sixty minutes, five segments, thirty-eight questions — each with the answer you're listening for, the follow-up to push with, and a three-way mark. She should not see this page. Mark as you go; the scorecard tells you what to spend the remaining days on.

Y — solid, moved on P — partial, needed prompting N — couldn't answer

Before you start

Set it up like the real thing

Sit across from her, not beside

Sounds trivial; it isn't. Being looked at while thinking is most of what makes an interview hard, and it's the part she can't practise alone.

Paper and pen, no laptop

Every coding question gets written by hand. If she reaches for a phone to check syntax, that's an N.

Run the clock and keep to it

Hit Start. When a segment's time is up, move on even mid-answer — real panels do, and rationing her own time is a skill she needs.

Don't help, don't react

No nodding along, no finishing her sentences. Let silences run. "Take your time" is the only assist allowed.

The one rule that makes this worth doing

Always ask the follow-up

Every question below has a PROBE. Ask it even when her first answer was perfect — especially then. The probe is where memorised answers come apart, and it's exactly what EPAM's panel will do.

Three probes that work on any answer:

  • "Why is that better than the alternative?"
  • "What breaks if you do it the other way?"
  • "Have you actually hit that on a project? What happened?"

Segment 1 · Java

15 MINUTES · 12 QUESTIONS · Q10–Q12 ON PAPER
01Walk me through the four OOP principles — and give me an example of each from a framework you've built.
What you're listening for

Abstraction (test calls loginAs(), never sees WebDriver), encapsulation (private locators in the page class), inheritance (BasePage), polymorphism (WebDriver d = factory.create("chrome"); overloaded click()).

Good signShe reaches for framework examples unprompted. A Dog-extends-Animal answer means she's reciting, not recalling.
Probe"Which of those is resolved at compile time and which at runtime?" — overloading compile, overriding runtime.
02Why is String immutable?
What you're listening for

Any two of: the string pool can safely share objects, hashCode is cached so it's a safe map key, thread safety without locking, security (values can't change after a check).

Probe"So what do you use inside a loop, and why?" — StringBuilder; + allocates a new String every iteration.
03Difference between == and equals(). And what's the contract with hashCode?
What you're listening for

== compares references (values for primitives); equals() compares content when overridden. Contract: equal objects must have equal hashCodes; the reverse isn't required.

Probe"What actually goes wrong if I override equals but not hashCode?" — the object lands in one bucket and is looked up in another, so HashSet.contains() returns false for an equal object. Silent failure. If she can't name the consequence, mark P.
04How does a HashMap work internally?
What you're listening for

hashCode → spreading function → bucket index. Collisions chain, compared by equals(). Default capacity 16, load factor 0.75 so it resizes at 12, and a bucket of 8 converts to a red-black tree (table must be ≥64 buckets) reverting at 6.

Mark Y only ifshe gets the numbers. "It uses hashing and buckets" alone is a P — that's the answer everyone gives.
Probe"What if two different keys have the same hashCode?"
05ArrayList vs LinkedList — and which do you actually use?
What you're listening for

ArrayList is array-backed: O(1) random access, but inserts in the middle shift elements. LinkedList is a node chain: cheap insert/remove at the ends, O(n) to reach a position. In automation it's ArrayList almost always.

Probe"When would LinkedList actually win?" — heavy insert/remove at the head or tail, i.e. queue/deque usage.
06Abstract class or interface for a BasePage — which, and why?
What you're listening for

Abstract class, because BasePage holds state (driver, wait) and shared concrete helpers, and a page genuinely "is a kind of" page. Interfaces for pluggable capability (ITestListener, IRetryAnalyzer).

Probe"Since Java 8 interfaces have default methods — so why not use one anyway?" — an interface still can't hold instance state or a constructor.
07Checked vs unchecked exceptions. Which kind are Selenium's?
What you're listening for

Checked = compiler forces handling (IOException). Unchecked = RuntimeException and below. Every Selenium exception extends WebDriverException extends RuntimeException — unchecked, which is why findElement needs no try/catch.

Probe"Should you ever catch a NoSuchElementException?" — rarely; only to convert it into a meaningful assertion failure, never to swallow it.
08What is ConcurrentModificationException and how do you avoid it?
What you're listening for

Fail-fast iterators check modCount; structurally modifying while iterating throws. Fixes: iterator.remove(), removeIf(), or iterate a copy.

Probe"Why does removing the second-to-last element sometimes not throw?" — hasNext() returns false first, so the check never runs. Bonus point if she knows this.
09Which Java 8 features do you use day to day in automation?
What you're listening for

Lambdas, streams, Optional, method references, default methods, java.time/Duration.

Strong answer"ExpectedCondition is a functional interface, which is why wait.until(d -> ...) works." That connects Java to Selenium and is a clear Y.
Probe"Intermediate vs terminal operations — what happens if there's no terminal op?" — nothing runs; streams are lazy.
10On paper: reverse a string without using StringBuilder.reverse().
What you're listening for
public static String reverse(String input) {
    char[] chars = input.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
        char temp = chars[left];
        chars[left++] = chars[right];
        chars[right--] = temp;
    }
    return new String(chars);
}
Mark onDoes it compile as written? Braces, semicolons, toCharArray(), correct loop bound. A right idea with broken syntax is a P — on a whiteboard, syntax counts.
Probe"Null or empty input?"
11On paper: find the second largest number in an array, without sorting.
What you're listening for

Two trackers, one pass, with the n != largest guard.

int largest = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
for (int n : numbers) {
    if (n > largest) { second = largest; largest = n; }
    else if (n > second && n != largest) { second = n; }
}
Probe — ask this one every time"What does your code return for {5, 5, 5}?" Without the != guard it returns 5, which is wrong. This is the whole question.
12On paper: from a List<Employee>, give me the highest-paid person in each department.
What you're listening for
Map<String, Optional<Employee>> topPaid = employees.stream()
        .collect(Collectors.groupingBy(
                Employee::getDepartment,
                Collectors.maxBy(Comparator.comparingDouble(Employee::getSalary))));
Mark ongroupingBy with a downstream collector. If she writes a loop with a map instead, that's still a P — it works, but streams are what's being tested.
Probe"Why is the value an Optional?" — maxBy returns one because a group could theoretically be empty.

Segment 2 · Selenium & framework

15 MINUTES · 10 QUESTIONS · Q1 IS THE BIG ONE
01Walk me through the framework you built. Take a couple of minutes.
What you're listening for

Time this one. Target is 90 seconds, hard ceiling 2 minutes. Structure: the problem it solved → the layers → data and config → how it executes in CI → one decision she owned, with a number.

Mark Y ifit lands under two minutes, has layers, and ends on a decision with a figure attached.
Probe"What would you change about it if you started again?" — a lead should have an answer. "Nothing" is a P.
02Implicit, explicit, fluent wait — explain the difference.
What you're listening for

Implicit = global, applies to every findElement, presence only. Explicit = one element, one condition, polls. Fluent = explicit plus polling interval and ignored exceptions.

Probe — the real question"What happens if I set both implicit and explicit?" They compound unpredictably; every internal findElement during polling inherits the implicit timeout. Answer must be "never mix them; implicit at zero." Anything vaguer is a P.
03Presence vs visibility — what's the difference and when does it bite?
What you're listening for

Presence = in the DOM. Visibility = in the DOM and rendered with non-zero size. Waiting on presence then clicking gives ElementNotInteractableException.

Probe"And which condition do you use before a click?" — elementToBeClickable, which is visible and enabled.
04You get StaleElementReferenceException on the second row of a table loop. Why, and how do you fix it?
What you're listening for

The cached WebElement points at a DOM node destroyed by the re-render. Fix: re-locate inside the loop by index, or wait for stalenessOf then re-find.

Lead-level bonus"I'd set the data up via API and skip the loop entirely."
Probe"Would you wrap it in a retry?" — acceptable as a last resort, but it can hide a real timing bug.
05ElementClickIntercepted — what causes it, and is a JS click a valid fix?
What you're listening for

Something else would receive the click: sticky header, modal, toast, overlay. Fix by waiting for the overlay to clear or scrolling into view.

The answer that marks a lead"A JS click bypasses the visibility check, so it can pass on a button no real user could reach. That's a false negative, and I'd challenge it in code review."
06How do you run tests in parallel, and what breaks when you turn it on?
What you're listening for

testng.xml parallel = methods/classes/tests/instances plus thread-count. Breaks: shared static driver, shared ExtentTest, shared test data, order dependence, shared output files.

Probe"How do you give each thread its own driver?" — ThreadLocal<WebDriver>. Then: "And what do you do in teardown?" — quit() and remove(). If she misses remove(), mark P and tell her why it matters.
07Give me the TestNG annotations in execution order, and tell me what a listener is for.
What you're listening for

BeforeSuite → BeforeTest → BeforeClass → BeforeMethod → Test → AfterMethod → AfterClass → AfterTest → AfterSuite. ITestListener.onTestFailure is where the screenshot and report entry happen.

Probe"Where would you put an assertion — can it go in @AfterMethod?" — no; a failure there is a configuration failure and can cascade into skips.
08What's new in Selenium 4 compared with 3?
What you're listening for

Any four: W3C protocol only, Options replaces DesiredCapabilities, relative locators, Duration-based timeouts, new window/tab API, CDP access, element screenshots, Selenium Manager, Shadow DOM support, rewritten Grid.

Probe"So do you still need WebDriverManager?" — not since 4.6; Selenium Manager resolves drivers itself.
09A test fails once in every ten runs. Walk me through what you do.
What you're listening for

Measure (invocationCount), classify the cause (timing / data / environment / order / genuine race), fix by cause, quarantine with an owner rather than delete, and track the flaky rate as a metric.

Listen for"The real cost is that people stop believing red means broken." That framing is the lead answer.
Probe"Your PM says just add a retry and move on. What do you say?"
10Write me the XPath for the Edit button in the row whose invoice number is INV-2043.
What you're listening for
//td[text()='INV-2043']/ancestor::tr//button[@title='Edit']
Mark onUse of an axis to traverse upward. If she writes a positional path like //tr[3]/td[5]/button, that's an N — it's the exact locator habit that causes flaky suites.
Probe"Could you do that in CSS?" — no; CSS can't match on text and can't go up the tree.

Segment 3 · API & REST Assured

10 MINUTES · 6 QUESTIONS · Q3 ON PAPER
01Explain the structure of a REST Assured test.
What you're listening for

given = request setup (base URI, headers, auth, params, body); when = verb and endpoint; then = assertions. Matchers come from Hamcrest via static import.

Probe"Where do equalTo and hasItem come from?" — org.hamcrest.Matchers.
02401 vs 403. And 400 vs 422.
What you're listening for

401 = not authenticated (no or bad token). 403 = authenticated but not permitted. 400 = malformed request. 422 = syntactically fine, business validation failed.

Probe"Which one do teams most often forget to test?" — 403: a valid user with the wrong role. It's the authorisation gap behind a lot of real security defects.
03On paper: log in, extract the token, then use it to GET a user and assert on the response.
What you're listening for
String token = given()
        .contentType(ContentType.JSON)
        .body(credentials)
    .when()
        .post("/auth/login")
    .then()
        .statusCode(200)
        .extract().path("access_token");

given()
        .header("Authorization", "Bearer " + token)
    .when()
        .get("/v1/users/101")
    .then()
        .statusCode(200)
        .body("email", equalTo("a@test.com"));
Mark on.extract() used correctly, and contentType present on the POST. Missing contentType is the 415 bug from her drills — worth noting if she omits it.
04PUT vs PATCH. Which are idempotent?
What you're listening for

PUT replaces the whole resource and is idempotent; PATCH is a partial update and isn't guaranteed to be. GET, PUT, DELETE, HEAD idempotent; POST not.

Probe"What's the classic defect with a badly implemented PUT?" — fields omitted from the payload get silently nulled.
05How would you stop every test repeating the same base URI, headers and token?
What you're listening for

RequestSpecBuilder and ResponseSpecBuilder, built once and passed via .spec(). Token generated once in @BeforeSuite and cached.

Probe"Why not just log in before each test?" — 200 tests means 200 auth calls, rate limiting, and failures that look like flakiness.
06Why would you push testing down from UI to API?
What you're listening for

Speed, stability, isolation of the failure, can run before the UI exists, and it's the fastest way to set up state for UI tests.

Listen for a real example"We moved setup steps to API calls and the flaky rate dropped." A concrete story here is a strong Y.

Segment 4 · Find the defect

10 MINUTES · 4 SNIPPETS · SHOW HER THE SCREEN

Turn the laptop round and let her read each snippet. Say nothing. Give her two minutes per snippet and mark on whether she names the defect and the mechanism.

01What's wrong here?
public class BaseTest {

    public static WebDriver driver;

    @BeforeMethod
    public void setUp() {
        driver = new ChromeDriver();
    }

    @AfterMethod
    public void tearDown() {
        driver.close();
    }
}
What you're listening for

Two defects. (1) static driver shared across threads — breaks in parallel with random NoSuchWindow/NoSuchSession. (2) close() instead of quit() — leaks driver processes on the CI agent.

Mark Y only if she finds both. One of two is a P. Most candidates spot the static and stop.
02This test is always green. The application is broken. Why?
@Test
public void verifyProfile() {
    SoftAssert soft = new SoftAssert();

    soft.assertEquals(profilePage.name(),  "Aishwarya");
    soft.assertEquals(profilePage.email(), "aishwarya@test.com");
    soft.assertEquals(profilePage.role(),  "Team Lead");
}
What you're listening for

Missing soft.assertAll(). SoftAssert collects failures and reports nothing without it, so the test can never fail.

Probe"How would you stop this happening across the team?" — enforce in code review, or extend SoftAssert and call assertAll from @AfterMethod. Bonus: "break the app once and confirm the test goes red — a test you've never seen fail isn't a test."
03The spinner clears in two seconds. This line sometimes blocks for over a minute. Why?
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(20));

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
wait.until(ExpectedConditions.invisibilityOfElementLocated(By.id("spinner")));
What you're listening for

Mixed waits. Each internal findElement during polling inherits the 20-second implicit wait, so the timeouts compound. Fix: implicit at zero.

Mark P ifshe says "don't mix them" without explaining the polling mechanism. The mechanism is the answer.
04Nothing throws and the code works. So what would you raise in code review?
public class LoginPage {

    WebDriver driver;

    public WebElement getUsernameField() {
        return driver.findElement(By.id("userName"));
    }

    public WebElement getSignInButton() {
        return driver.findElement(By.cssSelector("button[type='submit']"));
    }
}

// in the test
loginPage.getUsernameField().sendKeys("admin");
loginPage.getSignInButton().click();
What you're listening for

It's a locator dictionary, not a page object. Returning WebElement leaks the Selenium API into the test, there's no reuse, nowhere to put the waits, and no navigation model. Should be loginAs(user, pass) returning the next page object.

This is the lead-level question in the set. Finding a defect in working code is what separates senior from lead. A confident answer here is a strong signal.

Segment 5 · Leadership

10 MINUTES · 6 QUESTIONS · PUSH BACK ON EVERY ANSWER
01You've joined a team with 900 automated tests and nobody trusts the suite. First thirty days — what do you do?
What you're listening for

Measure before changing: pass rate, flaky rate, runtime, what's actually covered. Then quarantine the flaky ones so the pipeline is trustworthy again, fix by cause, and only then talk about adding tests.

Red flagJumping straight to "rewrite the framework." A lead diagnoses first.
02It's release day, forty tests are red, and the PM wants a yes or no. What do you say?
What you're listening for

Triage by cause first (real defects vs environment vs test bugs), assess by severity and area, then give a risk statement with a recommendation — and be explicit that the business owns the go/no-go while she documents the accepted risk.

Strong answer"I'll never say 'don't ship.' I'll say what's broken, who it affects, and what I recommend."
Probe — push hard"I don't have time for triage. Just tell me yes or no." See whether she holds the line politely or folds.
03How do you estimate automation effort for a new module?
What you're listening for

Classify scenarios simple/medium/complex with hours from history, add setup as a separate line, add 15–20% maintenance, name the buffer explicitly, and give a range with stated assumptions rather than one number.

Probe"Your estimate is 15 days and you're given 8. What now?" — cut scope, not quality: prioritise critical path, be explicit about what won't be covered.
04What metrics do you report upward, and which do you refuse to?
What you're listening for

Report: critical-path coverage, pass rate trend, flaky rate, execution time, defect leakage, detection stage. Refuse: test case count, defects raised — volume metrics that reward the wrong behaviour.

Naming what she won't report, unprompted, is a strong Y.
05Tell me about a time you disagreed with a developer or a manager. What happened?
What you're listening for

STAR, with evidence over opinion, the requirement as the anchor, escalating the question rather than the person, and a result where the decision was made and the relationship survived.

Red flagMaking the other person the villain. Listen for how she talks about them.
Probe"And looking back, was there anything you'd do differently?"
06What questions do you have for us?
What you're listening for

Three ready, and lead-level: state of the existing automation estate, team size and mix, where QA sits in the release decision, what success looks like at six months.

Mark N ifshe has none, or asks about salary or WFH in a technical panel.
